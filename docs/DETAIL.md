# 任务状态浮窗 / Task status window

把 DeepSeek Harness 工作区里的三类任务状态放进一个**系统级置顶窗口**，让你在切到别的应用时也能看到任务进展，并一键回到对应任务。

---

## ⚠️ 只支持 DeepSeek Harness **桌面版（Desktop）**

这个插件依赖**操作系统级的置顶窗口**，因此**只在 DeepSeek Harness 桌面版（Windows / macOS）上可用**，在 **dsh web 版本上不会工作**。

- 浮窗由插件自带的 Python + Tk 进程绘制，是真正的原生窗口，浮在所有窗体最前面；
- Web 版没有桌面外壳可依附：插件会照常出现在插件列表里，但宿主日志里会写明「当前运行环境没有桌面外壳」，并且不会拉起任何窗口。

这不是一个可以打开的开关，而是实现方式决定的：浮窗是系统级窗口，Web 版本的浏览器页面无法承载。

需要 Python 3（带 Tk）。DeepSeek Harness 自带的运行时里已经有一份；如果系统里找不到，可以用环境变量 `DSH_PYTHON` 指定解释器路径。

---

## 它显示什么

浮窗复刻了工作区侧栏里的三种状态提示：

| 状态 | 侧栏里的表现 | 浮窗里的表现 |
|---|---|---|
| 运行中 | 加载动画 | 转动的圆弧 + “运行中” |
| 待批准 / 待回答 / 计划待审 | 黄点 | 橙色圆点 + “等待处理” |
| 办结待确认 | 绿点 | 绿色圆点 + “办结待确认” |

状态来自宿主运行时的真实事实：Agent 的运行状态、审批与提问的等待、以及刚刚跑完还没确认的会话。列表按紧急程度排序（等待处理 → 运行中 → 办结待确认）。

## 顶部栏

顶部栏从左到右是：

- **“任务状态”**；
- **状态图标**：只有把任务列表**收起**之后才会出现 —— 列表展开时状态就在下面一行行写着，标题旁边不必重复；收起后列表看不见了，图标就成了唯一的提示。有运行中的任务显示转圈的加载图标，有待处理的任务显示黄点，有办结待确认的任务显示绿点；
- **三个图标按钮**（右端）：
  - **收起 / 展开**：收起后浮窗只剩顶部栏一行，再点一次展开；
  - **置顶 / 取消置顶**：切换浮窗是否浮在所有窗体最前面，这个选择会被记住；
  - **关闭**：关掉浮窗。之后可以在插件管理页里用「显示浮窗」重新打开。

浮窗的四个角是**真圆角**：窗口本身是直角矩形，但四角被抠成透明，浮窗外面不会露出一圈深色的直角框。收起时顶部栏的下边缘也跟着变成圆角。

## 任务列表

每一行就是界面里工作区会话题目行的样子：**左边一个状态点，中间是标题，右边是计时**，行高 32 像素，只有一行字（不再另起一行写「运行中」这类状态文字 —— 状态由左边的点表示）。

- **高度跟着任务多少走**：一个任务占一行，浮窗随之变高变矮。**没有任务时也保留一行的高度**，并显示「当前没有需要关注的任务」。
- **只有宽度可以调整**：拖右下角改宽度，高度始终由任务数量决定。宽度有下限：浮窗不会窄到把顶部栏挤坏 —— 标题、状态图标与三个按钮始终完整可见。
- 任务多到超过屏幕高度时浮窗封顶，剩下的用鼠标滚轮上下滚动，右侧会出现滚动条。
- **标题放不下时平时缩略成省略号**；**鼠标停在上面时改成走马灯**：按界面里工作区题目行的速度（0.03 像素/毫秒）把整条标题慢慢滚出来，滚到头就停住，指针移开就回到开头。

## 行尾那一格

行尾那一格与界面里工作区题目行末尾的规则完全一致：

- **等待用户处理的任务**写「待审批 / 计划待审 / 待回答」，不写计时；
- **其余任务**写计时：进入当前状态之后过了多久（刚刚 / N分钟 / N小时 / N天 / N个月 / N年）。

字号 10 像素、颜色取 `--dsw-alias-label-tertiary`。状态一变（比如从「等待处理」变成「运行中」），计时就从这个新状态的起点重新算；插件重启后计时会从「刚刚」重新开始，因为这段时间存在宿主的进程内存里。

## 状态从哪来

浮窗优先用**界面自己那份会话状态**：浏览器半侧每两秒把侧栏用的 `running / pendingInteraction / completionUnread` 回传给宿主，宿主合并后决定每一行显示加载图标、黄点还是绿点。

这样做的原因：审批请求走的是「瀑布式」事件，界面（以及别的应答方）会先把请求接走，插件事后补听是听不到的；而且插件启动之前就已经在等待的审批，事件早就发过去了。用界面的事实就不会漏。

同一个宿主上可能同时开着桌面窗口与浏览器标签页，两者看到的并不总是一样（审批请求只会被其中一个接住），因此宿主按页面分开保存、读的时候合并：「运行中」「办结未读」是两边共知的事实，取最新的一份；「等待用户处理」是谁报就算谁的。页面全部关掉超过十秒后回传过期，浮窗退回插件自己从运行时事件里推的结果。

每个页面回传时还会带上「我跑在哪儿」（桌面版还是浏览器标签页，见「交互」一节）。宿主据此知道桌面版窗口是否在场：它在场时，「切到某个任务」的请求只交给它；它不在场（例如只开了 web 版）时，浏览器标签页也可以领。

### 绿点是怎么消掉的

界面的「办结未读」是在**主界面里把这个会话读掉**之后才消失的 —— 会话一旦成了主视图，界面就把这个标记抹掉。

所以浏览器半侧除了报「哪些会话还亮着」，还要报「**刚刚还亮、现在不亮了**」的那一批（`cleared`）。宿主收到之后：

1. 给这些会话记一条「什么都不成立」的记录，合并时按时间取最新的一份，绿点随之消失；
2. 把宿主自己那份「刚跑完还没确认」的记录也删掉 —— 否则页面一关，绿点又会冒回来。

没有第 2 步的话，绿点会一直吊着：这正是之前「在主界面里读完了，浮窗上的绿点还在」的原因。


## 文本样式

行题的字号与行尾计时的字号都照着界面里工作区题目行取：标题 14 像素、正文色（`--dsw-alias-label-primary`）；计时 10 像素、次级色（`--dsw-alias-label-tertiary`）。字重都是常规，**不加粗** —— 界面里的题目行也不加粗。

### 字体怎么挑

界面（浏览器）按字形逐个回落：拉丁字形用 `--dsw-font-family` 栈里第一个装得下的字体，中文字形用系统的中文 **UI** 字体（Windows 上是「Microsoft YaHei UI」），笔画很细。

浮窗这边要分两件事处理，否则字会明显发粗：

1. **字体栈里的名字带引号**。主题给的是 CSS 写法（`"Segoe UI"`），Tk 不认带引号的名字，不去掉引号就会一路落到 Arial 这种兜底字体上去，拉丁字形与界面对不上；
2. **中文字形的回落字体不一样**。Tk 走 GDI，它的字体回落会挑「非 UI 款」的中文字体（笔画明显更粗），而不是界面用的那一款。

所以浮窗把字体分成两套：拉丁用字体栈里第一个装得下的字体（去引号后是 Segoe UI），中文直接点名用中文 UI 字体（`Microsoft YaHei UI` / `PingFang SC` / `Hiragino Sans GB` / `Noto Sans CJK SC` …）。每段文字按有没有中文来选，量宽度、截断、走马灯也都用同一套字体，保证排版不错位。

## 图标样式

浮窗里的图标直接照搬界面里的画法与尺寸：

- **状态点**：10 像素的方框里一个 6 像素的圆点（界面里圆点占方框的 60%），颜色取自 `--dsw-alias-state-warn-primary`、`--dsw-alias-state-success-primary` 等状态色；
- **加载图标**：14 像素的圆环 —— 一圈 25% 透明度的轨道，加一段会呼吸的圆弧，整体 1.5 秒转一圈；颜色与界面里的加载动画一样取 `--dsw-alias-label-tertiary`；
- **图钉**：直接用界面置顶按钮那枚 `pin-fill` / `pin-outline` 图标的路径 —— 置顶时钉身填实，取消置顶时只描边。

Tk 的圆弧没有圆头线帽，加载图标的圆弧是用一段圆头折线画的，因此圆弧两端与界面里一样是圆的；图钉则把 SVG 路径（直线段与三次贝塞尔）采样成多边形填充。

## 交互

- **点击一行**：请求宿主把焦点交给该任务，**在 DeepSeek Harness 桌面版窗口里**切到对应的任务页面；同时在 Windows 上用 Win32 把主窗口拉到前面。
  - 窗口原本是最大化的就**保持最大化**。Win32 的 `SW_RESTORE` 会把最大化窗口还原成初始大小，因此只有窗口确实处于最小化时才用它；其余情况只把它叫到前面。
  - 这个请求只交给桌面版窗口领取（浏览器标签页不抢），因为它才是用户眼前那个主体程序。桌面版窗口不在场时才轮到浏览器标签页；超过 15 秒没人领就作废。
- **拖动标题栏**：移动浮窗。浮窗被限制在虚拟屏幕内，不会被拖到找不回来的地方。
- 调整之后的宽度与位置会被记住：插件把它们写回自己的配置，**关闭 DeepSeek Harness 再启动，浮窗会以同样的尺寸出现**。

### 浏览器半侧怎么认出桌面版

桌面外壳把页面请求转给宿主时，会去掉浏览器的 `Origin` 与 `Sec-Fetch-Site` 标记（外壳自己就是那个边界），换上宿主签发的会话 cookie。因此：

- 宿主侧不再自己判断同源，改用宿主自带的信任栅栏 `connection.requestRejection`：Host/Origin 检查加上浏览器会话认证，桌面版与浏览器标签页都能过，本机上的其它页面一律拒绝。
- 浏览器半侧用 `location.protocol` 区分自己：桌面外壳用 `dsh-app://` 打开页面，浏览器标签页则是 `http(s)://`。这个区分随状态一起回传给宿主，宿主据此决定把「切到某个任务」的请求交给谁。

## 样式

浮窗跟随 DeepSeek Harness 的主题：底色、文字色与三个状态色都取自界面使用的 `--dsw-alias-*` 主题 token（状态色的映射与界面里状态点完全一致），字体取自 `--dsw-font-family`（中文另有一套，见「文本样式」），文案跟随界面语言。深色与浅色主题都会同步。

## 设置

在 **插件管理页 → 任务状态浮窗** 里可以直接用数值控制浮窗：

| 字段 | 含义 | 取值范围 |
|---|---|---|
| 浮窗宽度（像素） | 浮窗的初始宽度，也是当前宽度 | 240–1600 |
| 左边距 / 上边距（屏幕像素） | 初始位置 | −20000–20000 |
| 自动定位到屏幕右下角 | 打开时浮窗落在屏幕右下角；拖动过浮窗后会自动关掉 | 开关 |
| 刷新间隔（毫秒） | 浮窗向宿主要任务状态的频率 | 200–10000 |
| 显示浮窗 | 关掉以后浮窗进程退出，其余设置保留 | 开关 |
| 始终置顶 | 浮窗是否浮在所有窗体最前面 | 开关 |
| 列出办结待确认的任务 | 关掉以后只显示运行中与等待处理的任务 | 开关 |

浮窗的高度由任务数量决定，因此没有高度字段。数值超出范围时输入框会直接给出提示，不会写进配置；万一窗口还是被弄到屏幕外，把左边距与上边距填成想要的数值再「应用」就能把它拉回来。

页面底部的三个按钮：**应用**写入改动过的字段，**放弃改动**丢掉尚未写入的编辑，**恢复默认**把所有字段恢复成插件的默认值（360 宽、落在屏幕右下角）。

## 已知边界

- 浮窗需要 Python 3 与 Tk；没有解释器时插件会在宿主日志里给出提示，其余能力不受影响。
- 浮窗进程崩溃后会自动重新拉起；宿主退出时浮窗也会跟着退出。
- 任务列表的滚动靠鼠标滚轮，没有键盘导航。
- 行尾计时在插件重启后从「刚刚」重新开始（这段时间存在宿主内存里，没有写盘）。
- 绿点跟着界面走：主界面里把任务读掉之后，浮窗上的绿点会在几秒内一起消失。
